# 知识核心 SDK 合同

Go module 为 `github.com/JieWaZi/neux-knowledge`，公开入口是 `core`。生命周期与生成端口见 [core/organize.go](../core/organize.go)，业务输入和持久模型见 [领域输入](../internal/domain/inputs.go)、[领域对象](../internal/domain/entities.go)。SDK 不暴露 GORM，调用者不需要导入 internal。

## 存储与业务入口

`Open` 需要独立 SQLite 文件和受管 raw 根目录，`Close` 释放资源。原件保留上传原字节，上传不触发模型。库、原件、Wiki、主题、修订、索引、核查、导出与删除分别通过 core 业务方法访问；CLI 当前操作以 `discover` 为准。

写入携带明确请求标识和期望版本。已有页面的整页改写必须原样回传读取时的 `Page.UpdatedAt`（毫秒精度），不能用提交前新查询的时间替换；缺失或过期会冲突。原件由稳定 `SourceID` 与不可变 `SourceVersionID` 共同定位：显式指定 `SourceID` 重新导入产生新版本；作为新来源上传时，按上游规则复用同库、同内容哈希和同文件类型的当前有效来源，失败或删除中的来源不阻止重新上传。复用返回本次请求的持久回执，不创建来源或重复记录资料创建活动；普通整理继续跳过已处理来源。重建保留原件并清除所选版本的派生块、向量和摘要。Wiki 的来源证据保留实际版本、摘要和位置。

`LintLibrary` 只读核查，不执行修复。`AutoFixLibrary` 复用上游断链、短正文和失效来源修复规则，输入固定请求身份、目录及权限版本；页面变更、历史、回执和活动在同一事务提交，修复后重建反链。人工保护内容与索引页不自动修改；短正文按上游少于50字节规则归档，失效来源只清理已删除或归档的来源，出现新版不自动移除旧版证据。返回实际变更页数及修复后当前核查结果，语义重复和事实争议留给受限修复 Agent。SQLite 相似页候选直接采用上游按词边界补空格的三元组 Jaccard 排序与0.3阈值，不使用关键词包含匹配代替。

## 直接模型与阅读端口

`Generator.Generate(ctx, GenerateRequest)` 只接收本次 `Messages` 和模型参数，返回 `GenerateResult.Text` 原文、`FinishReason`、真实用量与原生能力诊断。`JobID`、`SourceVersionID`、`StageID`、`Stage` 只用于知识诊断，不是聊天或通用执行身份。

普通 Wiki 调用温度0.3、Thinking=false、输出预算32768；普通文档档案使用原系统模板与独立用户正文、8192 rune输入采样、1024输出预算，并拒绝length截断。模型端口不得跨请求保留会话，不获得文件提交、CLI或工具权限。只有一次页改写遇length时，由核心在该次改写内部携带已返回片段，最多额外续写3次；仍截断时保留原页。

`ReaderPort` 收到固定原件字节与身份，返回实际覆盖、块、原文rune范围和确认位置。partial、unsupported与实际读取失败不能升级成完整阅读。`PrepareDocument` 负责实际分块和必要的原始文档索引；可调用 `PrepareIndexedDocument`。Wiki 引用使用已持久的实际子块，重叠内容按上游 `MergeTextChunks` 重建。可选 `Embed` 提供冻结的真实嵌入能力，供上游目录相似度筛选使用；不可用时沿上游有界目录回退。

调用方需要动态撤权时，将同一宿主闸门传入 `OrganizeInput.PublishGuard` 与用于索引的 `DocumentEmbedder.PublishGuard`。页面、索引导言和链接维护在提交前复核；原件索引在外部嵌入返回后取得闸门并覆盖分块与向量持久化。外部模型与嵌入请求不持发布锁，撤权无需等待网络返回，迟到结果不得落库。

## 接纳、运行与发布

`AcceptJob` 冻结来源、权限和库配置，不调用模型。不同原件可继续接纳为 queued 任务；同一原件的任意版本已排队或处理中时，在接纳事务内拒绝整次重叠请求，重试同样核对占用。原件上传独立保存，不扩大已接纳任务范围。`SourceActivity` 与来源查询汇总全部在途任务，而非只展示队首。`SourceVersion.OrganizeBlocked` 是按逻辑原件身份投影的非持久占用标志；活动任务内已经成功或失败的来源仍然保留占用，展示状态和诊断保持真实结果，候选选择与重建须同时检查该标志。

`RunOrganize` 读取持久任务，以库级系统文件锁按接纳顺序串行执行；同毫秒接纳以单调递增的尝试接纳时间排序，重试排在现有等待任务之后。正在处理或取消中的任务优先恢复。等待者可取消 Context，取消等待不改变已接纳任务；宿主须恢复所有未终结任务的驱动。队首开始时取得当前目录版本，模型、权限和文件范围保持原快照；已开始的任务不刷新目录屏障。库锁被旧任务持有或尚未轮到时等待，不丢弃任务。默认batch=5、Map=10、Reduce=10、cite=4；WikiConfig沿固定上游规则覆盖相应批次参数。

已有 Wiki 的独立 ACP 维护通过 `AcceptJobInput.Maintenance=true` 接纳，要求 Wiki 已开启、空来源、禁止重建及仅含 `maintain` 的权限快照。`IsMaintenanceJob` 从已有任务字段识别此类任务，不增加持久列。维护与原件整理共用库队列；宿主以 `ActivateQueuedJob` 启动队首，并以 `WithMaintenanceJob(ctx, job.ID, job.Attempt)` 绑定每次工具回调。Wiki 页面和目录的真实写入事务同时核对任务仍在处理、尝试未变化、未取消、同一知识库及原权限策略仍有效，迟到回调不能写入；此上下文禁止原件导入与处理。维护任务不进入 `RunOrganize` 的来源管线。

激活维护任务时建立当前尝试的 `wiki_maintenance` 阶段，恢复沿用该阶段；`CompleteMaintenanceJob` 以当前任务版本保存实际最终报告并将阶段和任务结算为成功，原件状态保持原值。宿主使用普通任务上下文调用完成、失败和取消入口，以便回执重放仍可返回原始结算结果；仅工具执行上下文携带维护写屏障。失败、取消、重试沿用原有任务入口，旧阶段审计与已提交 Wiki 内容保留。

Wiki 文档使用Pass0候选提取，失败时回退旧完整提取器；长文Wiki摘要在原输入预算内按全文分布选取完整表行，并补充首中尾正文样本，明确标注省略，不能把采样视为全文覆盖；文档内语义去重后并行生成Wiki摘要与块引用。引用单批失败不取消兄弟批次，未知块句柄被丢弃，无引用知识使用真实文档级Details回退。精确已有身份优先，批次内身份保留和cite后reclaim防止重复页面。

整个批次先统一目录规划，再按slug聚合来源归并。精确地址读取包含归档页；同地址重新产生有效贡献时沿原页面身份更新，不新建冲突地址；仅对版本大于1的换版来源，按同批稳定来源身份、以每批最多100页的slug游标查询完整已发布及归档贡献集合，即使新版不再产生原主题也在Reduce前补撤回旧版本贡献；旧摘要已换版则按每个确切旧版本读取保留修订；历史混合版本证据不证明摘要属于其中任意一版，必要时完整回读该旧版本原件，全部旧版本材料逐版标明且不静默截断。无法完整恢复时保留原页和证据，短暂存储错误保留原类别进入既有重排，不撤回其他来源。归档页只撤回旧贡献时保持归档，有新增贡献时才沿原身份重新发布。人工保护和版本校验仍生效。换版通过稳定SourceID读取旧页面与旧摘要，同主题发出retract+addition，消失主题发出retractStale；适配层据此移除旧版本证据，只添加本次真实引用；整页替换的资料摘要同样按稳定来源身份替换旧版本证据。已有人工位置和保护内容继续由短事务校验。

页面生成失败保持原页；未能创建的新知识链接从该批摘要清除。短暂写入失败使相关来源重排。单份来源的机器摘要按当前不可变来源重新生成，专用发布路径校验来源身份、SHA、完整阅读结果、稳定摘要地址与非空完整模型结果；旧摘要的归纳表改为段落、重新编号或列归纳变化不套用多源页面的表格首列保留规则。摘要仍执行人工保护、读取时间与页面版本校验，并替换为当前来源证据；概念和实体合并继续执行原表格保护。成功兄弟页面保持发布。调用瞬态重试最多3次，等待2秒、4秒。文档待办初次加最多5次重排，失败次数和NotBefore持久化，第6次失败进入dead；普通重排5秒，限流60秒。确定性阅读能力限制与来源失活直接结算，不消耗模型重试预算。

页面、修订、来源结论和回执在SQLite事务内保存，检查任务尝试、取消、权限、来源存活、目标页面和目录版本。模型文本不能直接写Wiki。每次页面提交同时写持久finalize增量，所有待办收束后统一更新索引和affected页链接；页面收尾意图归同一整理任务所有，显式重试保留旧尝试尚未完成的索引与链接工作；索引发布与任务级增量集合检查点、逐项文档变化消费回执同事务提交，恢复核验当前任务权限、尝试、目录版本及页面读取快照，只把未消费文档变化交给索引模型；已提交索引不重复生成，旧尝试级索引回执核验后沿原页面保留；链接维护沿持久页面意图确定性重入。归档索引沿原身份更新，人工或其他任务改写仍受版本保护；首版索引最多200份近期摘要，增量只发送已有简介与本次变化。索引模型失败沿上游默认或保留旧简介。链接维护先修复可安全解析的坏slug，再对affected页的已有链接与新写入标题做自动链接，不改动无关页面；链接维护以内容版本和读取时间校验后提交，不增加内容版本或历史快照。

显式整理使用上述同一次Run收束全部待办和一次finalize，替代上游Asynq触发器和20秒debounce；同库互斥、持久待办和局部失败规则保留。当前产品在Wiki开启时走Wiki摘要，Wiki关闭时走普通文档档案，不声称复现上游完整post_process调度或单独SummaryEnabled开关。

## 取消、恢复与诊断

内部生命周期使用 `CancelOrganize` 先立持久屏障，再同步取消Run的Context；不提供用户停止整理入口。阅读、模型或索引真实结束后结算屏障，已发布页保留。`FailOrganize` 供模型准备或运行的不可恢复故障结算：未完成来源失败，成功来源与页面保留；宿主关闭导致的Context取消不调用此入口，以便重启恢复。

进程退出后，系统文件锁自动释放。恢复把未返回的纯知识阶段标为中断，继续持久来源待办；未完成来源优先恢复已提交的文档提取计划，缺失时才执行 Map；不把一次 transport 成功的坏 JSON 当作可复用产物。完成来源不重新领取。`RetryJob` 创建新尝试，并重新检查权限与来源，旧尝试不能影响新尝试。

`Stage` 保存当前任务尝试、来源读集、真实输入、结果文本、停止原因、解析或调用错误、用量和原生诊断。`OrganizeSourceWork.StartedAt` 是实际开始Reader前提交的事实。`OnProgress` 只在来源开始与重排事实提交后通知宿主；`OnPublished` 只报告真实提交回执，二者不拥有状态或回滚权。

开发阶段结构版本固定为1，保存在 `knowledge_schema` 的唯一记录中。空数据库一次性建立当前全部表与索引；已有数据库只校验版本、完整表、列与必要索引，不补列、不执行历史迁移，也不识别或处理旧任务和候选表。开发数据由维护者在应用关闭后显式整理。

所有验证依靠稳定ErrorCode与原始技术诊断；不依赖错误文本决定授权。真实模型质量、CLI能力限制和远端部署仍需相应环境验收。

## 部分失败恢复与历史保留

结构化模型响应先解析原始 JSON，再在已解析的字段中安全还原图片地址；标准代码块与 BOM 包装可归一，解析失败按原文失效阶段缓存。Wiki 摘要与页面改写遇到长度截断最多续写三次，持续截断或空续写不发布半截结果。

同一整理任务保存已完成的文档提取计划，显式重试复用已通过当前模型完整性与解析校验版本的计划；旧版 Wiki 计划先核对来源身份与 SHA，再重新组装，避免旧截断摘要绕过校验。已成功的完整模型阶段按完整输入复用结果。每份来源对页面的贡献以任务、不可变来源版本、目标地址和贡献职责识别（实体与概念均属新增贡献），模型正文、引用和提示上下文变化不产生新身份；贡献回执与页面写入同事务提交。旧计划中的完整内容哈希只用于核对真实已提交回执并沿原回执映射稳定身份，不凭重新生成的结果确认成功。恢复或局部重试只合成尚未应用的贡献，已成功页面不重复调用模型；来源撤回、任务取消、尝试变化及发布权限仍逐次校验，不跨任务复用结果。

同实例的短数据库事务采用可取消准入，模型请求不持该准入；跨进程 SQLite busy 仍重试完整事务。短暂模型故障保留既有退避与失败预算；明确的权限失败、格式或长度失败、概念或实体的表格行保护拒写直接保留失败诊断，不反复生成整份资料。页面失败包含目标地址；表格拒写包含丢失与原有行标识数。部分成果保留，失败来源不冒充已完成。

同一整理任务对每页最多增加一个内容版本，任务身份不随自动恢复或显式重试改变；新页始终为 v1，已有页仅首次可见内容变化递增一次，后续批次合并到该版。内容未变、来源证据刷新及自动链接维护不生成修订。首次替换前的历史快照保持不变，成功贡献回执与页面同事务；人工或另一任务替换该版本后，旧任务继续写入会发生冲突。整页写入使用版本与毫秒严格递增的读取时间共同校验，不以合并内容版本绕过迟到响应保护。

修订裁剪在页面或自动维护写入事务中执行：统一保留每页最近 50 个版本（当前版本加最多 49 个历史快照），不区分自动、人工、智能体或恢复来源；当前页面和递增版本号不受裁剪影响。读取历史不会清理快照。

## 模型与检索边界

核心向Generator保留原system/user/assistant消息顺序和正文。NeuxAlly的Codex独立文本适配使用临时原生主目录，只沿用认证与provider连接；原system正文通过model_instructions_file替换内置基础指令，原user正文直接发送。仅user调用因原生CLI要求基础指令非空，使用明确记录的中性适配句，不把它称为上游system。关闭AGENTS读取、内置skills与自动skills指令，清除模型目录的代码助手指令；普通Chat不走此路径。assistant续写历史及其他Runtime仍经ACP文本序列化，其限制明确诊断。原生权限/会话元数据和部分工具定义仍可能存在，Thinking、输出上限与温度是否可控以本次Diagnostics为准，不声称完整Chat API等价或内容质量已经等效。

Wiki-only不要求Embedding。固定上游的vector与keyword都调用检索引擎BatchIndex，二者均要求Embedding；本地vector要求Embedding，keyword使用SQLite关键词分支，因此不要求Embedding。GraphEnabled对应上游独立实体关系抽取，不是Wiki页面出链和反链；本地未接入实体关系抽取。Wiki出链来自正文wikilink及上游Finalize标题匹配，反链由出链投影；生产Finalize不匹配新页别名，也不把不相干全文强行链接。


## 原件检索

原件关键词检索使用 FTS5、中文 bigram 分词与 BM25。向量只保存在 sqlite-vec 的 vec0 虚表；分块模型的 Vector 仅承载本次输入，不作为 JSON 持久列。查询先限定知识库及向量空间，再取 Top-K；候选正文按身份有界回读。关键词与向量同时输入时按 k=60、向量权重0.7和关键词权重0.3进行归一化 RRF 融合。单路失败明确返回错误，不伪装成无匹配或降级成功。

分块与关键词索引在同一事务内显式同步维护；向量写入、来源重建、来源删除及整库删除在原业务事务内同步处理。空库建立全部结构，重新打开只校验当前结构，不迁移历史数据、不回填旧索引，不自动清空数据库。向量表按实际维度建立；缺失索引明确报错。

知识核心使用独立的 ncruces SQLite 连接与 sqlite-vec WASM 绑定，保留无 CGO 构建；GORM 仍是持久化入口。中文分词在 Go 写入与查询入口执行；驱动仅注册既有文件名匹配函数，该函数只读输入，不访问文件、网络或凭据。保持 SQLite 默认日志模式和默认连接池；将驱动自带的默认忙等待还原为原生零等待，由核心完整事务重试处理竞争。该连接、数据和生命周期归知识核心所有，不依赖任何宿主记忆模块。

## 轻量页面目录

`Engine.ListPageDirectory(ctx, libraryID, offset, limit)` 返回独立 `PageDirectoryEntry` 与真实总数，默认及单批上限为 `PageDirectoryMaxLimit`（1000）。结果只含页面身份、所属库、地址、标题、类型、简介、目录归属、路径、排序和版本。数据库在短读事务内计数并显式投影，默认排除归档和软删除，按 `updated_at DESC, id ASC` 稳定分页。正文和结构化证据通过 `GetPage` 或 `GetPageBySlug` 独立读取。`CountPagesByTheme` 一次分组统计有效页面数量，不逐目录读取正文。
